# noreliq — сайт-визитка

Сайт студии цифровой разработки **noreliq**. Next.js (App Router) + TypeScript + Tailwind CSS v4 + GSAP.
Весь контент на этом этапе — заглушки; архитектура заложена так, чтобы замена текстов, цен и фирменного
стиля не требовала перевёрстки.

## Команды

```bash
npm run dev     # дев-сервер на http://localhost:3000
npm run build   # продакшн-сборка (все страницы статические)
npm start       # запуск собранного приложения
npm run lint    # ESLint

node scripts/generate-placeholders.mjs   # перегенерировать SVG-плейсхолдеры в public/placeholders
```

## Публикация на GitHub Pages

Демо-стенд собирается и выкладывается автоматически: пуш в `main` запускает
`.github/workflows/deploy.yml`. Один раз нужно включить публикацию в настройках
репозитория: **Settings → Pages → Source → GitHub Actions**.

Адрес: `https://<owner>.github.io/<repo>/`

Статический режим включается **только** переменными окружения, которые выставляет
workflow, — локальные `npm run dev` и `npm run build` работают как раньше, под будущий
свой домен и сервер:

| Переменная | Зачем |
|---|---|
| `GITHUB_PAGES=true` | включает `output: "export"`, `trailingSlash` и свой загрузчик картинок |
| `NEXT_PUBLIC_BASE_PATH` | префикс пути (`/noreliq`), без него на Pages отвалятся стили и картинки |
| `NEXT_PUBLIC_SITE_URL` | адрес для `sitemap.xml`, canonical и OG |

Собрать экспорт локально (результат — папка `out/`):

```bash
GITHUB_PAGES=true NEXT_PUBLIC_BASE_PATH=/noreliq npm run build
```

### Переезд на свой домен

Убрать из workflow `NEXT_PUBLIC_BASE_PATH` (и `GITHUB_PAGES`, если хостинг
будет с сервером) — префикс исчезнет сам, правки кода не нужны. Ссылки, картинки
и метаданные собраны относительно этих переменных.

Особенности статической сборки, заложенные в проект:

- `dynamic = "force-static"` в `sitemap.ts`, `robots.ts`, `opengraph-image.tsx` — без этого экспорт падает;
- свой `image-loader.ts`: с `images.unoptimized` Next не подставляет `basePath` и картинки отдают 404;
- префетч ссылок отключён на статике — Next кладёт RSC-пейлоады не туда, откуда их просит роутер;
- `public/.nojekyll` — иначе Pages выкидывает папку `_next`;
- демо закрыто от индексации в `robots.txt`, чтобы не конкурировать с основным доменом.

## Структура

```
/                    Главная: hero, манифест, лента проектов, услуги
/about               О нас: лид, цифры, принципы, стек, команда
/services            Услуги: тарифные пакеты + этапы работы
/projects            Проекты: сетка кейсов
/projects/[slug]     Кейс: hero, мета, блоки контента, «следующий проект»
/contacts            Контакты: email, телефон, соцсети, реквизиты
```

## Где править контент

Ни одной строки текста нет прямо в JSX — всё лежит в `src/content/`:

| Файл | Что внутри |
|---|---|
| `src/content/site.ts` | название, слоган, email, телефон, город, соцсети, реквизиты, SEO-дефолты |
| `src/content/nav.ts` | пункты меню (единый источник для шапки, мобильного меню и подвала) |
| `src/content/services.ts` | тарифные пакеты и этапы работы |
| `src/content/projects.ts` | кейсы: мета, обложка, блоки контента |
| `src/content/about.ts` | лид, принципы, стек, цифры, команда |

### Цены

В `services.ts` у каждого пакета поле `price: number | null`. Пока везде `null` — в интерфейсе
рендерится «По запросу». Как только появятся цифры, достаточно проставить число: форматирование
(`Intl.NumberFormat`, рубли) уже реализовано в `src/app/services/page.tsx`.

### Изображения

Плейсхолдеры — локальные SVG в `public/placeholders/`, генерируются скриптом
`scripts/generate-placeholders.mjs`. Внешние сервисы не используются. При замене на реальные
фотографии достаточно положить файлы в `public/` и поправить пути в `projects.ts` / `about.ts`.

## Фирменный стиль

Все цвета, шрифтовая шкала, тайминги и кривые анимаций — CSS-переменные в блоке `@theme`
файла `src/app/globals.css`. Ребрендинг = правка одного этого блока:

- `--color-bg`, `--color-bg-alt`, `--color-fg`, `--color-muted`, `--color-line`, `--color-accent`, `--color-inverse`
- `--text-hero / display / h2 / h3 / lead / body / label` — размеры на `clamp()`, доступны как Tailwind-утилиты
  (`text-hero`, `text-display`, `text-h2`, …)
- `--dur-fast / base / slow`, `--ease-out-expo`, `--ease-in-out-quart`
- `--gutter`, `--header-h`

Шрифты подключаются через `next/font` в `src/app/layout.tsx` и попадают в токены
`--font-display-src` / `--font-sans-src`. Сейчас это Manrope (дисплейный) и Inter (текст), оба с кириллицей.

## Анимации

Ядро в `src/components/motion/` — переиспользуется всеми страницами, GSAP-код по секциям не дублируется:

| Компонент | Назначение |
|---|---|
| `SmoothScroll` | Lenis + синхронизация с GSAP-тикером и ScrollTrigger |
| `PageTransition` | прелоадер-счётчик при первой загрузке и шторка при смене маршрута |
| `TransitionLink` | внутренняя ссылка: сначала шторка, потом переход |
| `SplitReveal` | построчный/пословный ревил текста через SplitText |
| `Reveal` | ревил нетекстовых блоков и каскад по карточкам |
| `MagneticLink` | магнитное притяжение к курсору |
| `Cursor` | кастомный курсор с состояниями (скрыт на тач-устройствах) |
| `Grain` | шумовой оверлей на SVG-фильтре |
| `ParallaxImage` | обложки с параллаксом по скроллу |

### prefers-reduced-motion

Хук `src/lib/useReducedMotion.ts` — единый источник правды, ему подчиняется каждый компонент выше.
Инлайн-скрипт в `layout.tsx` ставит на `<html>` класс `motion-ok` только если движение разрешено;
все «спрятанные до анимации» состояния в CSS висят на этом классе. Поэтому при включённом
«уменьшить движение» контент виден сразу, прелоадера и шторки нет, Lenis и курсор не инициализируются.
